## 真实模型验证（2026-10-04）

首次完成真实 DeepSeek 调用。此前所有"验证"均为模拟响应，没有任何真实网络请求。

- **配置事故（已修复）**：`.env` 第 3 行缺少换行，`LLM_BASE_URL=https://api.deepseek.com` 被粘在 API key 之后。`read_env_file` 按第一个 `=` 切分，72 字符整体被当作 key，`--check-api` 返回 HTTP 401。修复为独立行后，key 还原为 35 字符（`sk-`+32 位）。**属纯配置错误，代码无需修改。**
- `--check-api`：2 次模型请求、1 次工具调用、529+107 token、1.7 秒；模型正确调用 `get_weather` 并如实说明数据为虚构教学数据。
- `--live --rain --budget 80`：8 次模型请求、13 次工具请求、2 次终审，13 秒生成 2 站 77 元方案，未超 80 元预算。
- `--evaluate --live` 连续 3 次：12/12、12/12、11/12 = **35/36 = 97.2%**。199 次模型请求对应 199 次 HTTP 尝试，**未触发任何 429/5xx 重试**。输入 719,665 token、输出 38,984 token，估算成本约 0.88 元（空闲时段，未计缓存命中）。
- **修复后复测**：完整真实评测 12/12（75 次模型请求、中位 8.9 秒、约 0.33 元），原失败用例 `meal_under25` 定向复测 6/6 正确。
- 单例平均：5.5 次模型请求、约 0.022 元、中位耗时 7.7 秒。离线基线为 0 次请求、约 0.001 秒。
- **自我修正证据**：一次真实规划中模型先提 171 元（被拒）、再提 126 元（被拒）、最终收敛到 77 元，全程只依赖 `check_itinerary` 返回的 `issues`，无人工干预。
- **唯一失败用例（已修复并验证）** `meal_under25`（预算 20 元 + 要求用餐）返回 `error` 而非 `no_plan`。根因：`tools.check_itinerary` 没有 `include_meal` 参数因而不检查用餐要求，而 `finalize.verify_final` 检查，工具层给出假绿灯后模型连续三次终审失败。修复方式：照搬既有 `rain` 模式，把 `include_meal` 作为用户级约束在构造 `TripTools` 时注入，模型无法通过工具参数放宽；`verify_final` 的独立检查保留作为纵深防御。修复后真实评测 12/12，原失败用例定向复测 6/6 正确。
- **头号未修复问题**：模型常把最终 JSON 包在 Markdown 代码围栏中，触发 `json.loads` 失败。修复循环能救回正确答案，但**几乎每次会话都多烧一轮完整上下文**（约 2–4 万输入 token），且错误提示是 Python 原文。详见 `reports/README.md`。
- **证据固化**：`outputs/` 被 Git 忽略，若不另存则 GitHub 上看不到任何真实数据。原始报告与 trace 已复制到 `reports/`，说明见 `reports/README.md`。
- 本次真实调用合计 339 次模型请求、1,176,869 输入 token、62,186 输出 token，按官方价目折算约 1.43 元（空闲时段，未区分缓存命中）；修改后 58 项单元测试仍全部通过。
