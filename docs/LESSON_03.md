## 2. 为什么把时间转换成整数

我们希望计算`结束时间 + 交通分钟数`。`"11:30"`是字符串，直接加15会报类型错误；字符串拼接也不是时间运算。

`to_minutes("10:30")`的执行过程如下：

```python
parts = "10:30".split(":")   # ["10", "30"]
hour, minute = map(int, parts)  # 10、30
answer = hour * 60 + minute    # 630
```

`map(int, parts)`把列表里的每个字符串转换成整数。左边两个变量接收两个结果，叫解包。

| 原字符串 | 小时×60 | 分钟 | 距午夜总分钟数 |
|---|---:|---:|---:|
| 10:00 | 600 | 0 | 600 |
| 11:30 | 660 | 30 | 690 |
| 11:45 | 660 | 45 | 705 |
| 12:00 | 720 | 0 | 720 |
| 13:00 | 780 | 0 | 780 |

`format_time(705)`反过来算：`705 // 60`得到11，`705 % 60`得到45，因此输出`11:45`。`//`是整除，`%`是余数，`:02d`把一位整数补成两位。

格式检查先拒绝`"9:5"`、`"25:00"`、`"+1:30"`等输入。不能指望后面的路线计算替你识别错误格式。项目目前只支持同一天，不支持23:00到次日01:00。

## 3. 一条教学路线怎么计算

地点表中p01坐标为`[0, 0]`，f01为`[1, 0]`。`get_route`使用网格距离：

```text
distance = |0−1| + |0−0| = 1
minutes = 5 + distance × 10 = 15
fare_per_person = 2
```

`zip(source["position"], target["position"])`先产生`(0,1)`和`(0,0)`两对坐标。`abs(a-b)`求每一对的差的绝对值，`sum(...)`再加起来。

这是为了学习而定义的公式，不是实时地图。相同ID到相同ID时，函数返回0分钟、0元；但是最终行程会另外拒绝重复地点，所以“路线允许查询自身”和“行程允许重复”是两个不同规则。

## 4. 逐行跟踪两站行程

输入是一个列表，每个元素是一个字典：

```python
stops = [
    {"place_id": "p01", "start": "10:00"},
    {"place_id": "f01", "start": "12:00"},
]
```

开始循环之前：

```python
issues = []                       # 记录所有发现的冲突
schedule = []                     # 装计算后的行程
cost = 0.0                        # 每人累计费用
previous_id = None                # 目前没有上一站
previous_end = 600                # 用户可用时间从10:00开始
seen = set()                      # 已访问的地点ID，集合方便查重
```

第一轮拿到p01。`arrival=600`，`finish=600+90=690`。因为`previous_id is None`，跳过相邻交通计算；本项目不计算从家到第一站的交通。地点费用为0，所以`cost`仍为0。

检查完以后，往`schedule`添加一条记录，再更新上一站状态：

```python
previous_id = "p01"
previous_end = 690
```

第二轮拿到f01。到达时间是720，待60分钟，因此结束时间为780。此时已经有上一站，调用`get_route("p01", "f01")`得到15分钟、每人2元。

```text
最早可到达 = previous_end + route.minutes = 690 + 15 = 705
实际到达   = 720
720 < 705 为 False，因此不存在交通衔接不足
```

这允许中间留白：705到720这15分钟可以是等待。程序没有要求整天排满。

随后累计费用：`0 + 2 + 35 = 37`。最后全组费用是`37 × 3 = 111`。

| 循环位置 | cost | previous_id | previous_end | issues |
|---|---:|---|---:|---|
| 刚开始 | 0 | None | 600 | [] |
| 公园结束 | 0 | p01 | 690 | [] |
| 面馆结束 | 37 | f01 | 780 | [] |

逐站实验会用真实工具输出打印这组数字，并检查累计费用与正式函数一致。

## 5. 为什么发现错误后还继续算

`check_itinerary`没有在第一次冲突时立刻结束，而是把问题放进`issues`。这样模型能一次看到“交通时间不足”和“预算超出”等多个问题，减少来回修正次数。

`valid = not issues`利用了Python的真假规则：空列表为假，因此`not []`为真；有错误的列表为真，取反后就是假。

注意两层含义：

```python
{"ok": True, "data": {"valid": False, "issues": ["预算超出……"]}}
```

- `ok=True`：工具成功接收参数并完成计算。
- `valid=False`：计算结果发现这份行程不可行。

如果时间字符串本身坏了，函数会抛`ValueError`，注册表返回`ok=False`。前者是“成功检查出问题”，后者是“连检查都没正常完成”。

## 6. 约束逐个对应代码

| 需求 | 程序比较什么 | 一个失败例子 |
|---|---|---|
| 不能重复地点 | ID是否已在seen中 | 两次p01 |
| 能赶到下一站 | arrival ≥ previous_end + route.minutes | 11:44到面馆 |
| 在用户时间内 | arrival ≥ window_start且finish ≤ window_end | 12:30必须结束，却13:00才离开 |
| 在营业时间内 | 到达不早于open，结束不晚于close | 闭馆前5分钟到，却要玩60分钟 |
| 雨天室内 | rain为真时地点indoor也为真 | 雨天去p01 |
| 每人预算够 | cost ≤ budget_per_person | 预算36，费用37 |

“到达时还营业”不够，还要检查离开时是否已经关门。另一个容易漏掉的地方是，预算比较用**每人费用**，不是全组三人111元去和每人37元比较。

## 7. 先自己做，再展开答案

**练习A：** 把面馆到达时间分别改为11:44、11:45。谁通过，为什么？

<details><summary>参考推演</summary>

11:44为704分钟，比705早1分钟，所以交通不足。11:45恰好705，比较条件是`arrival < earliest`，相等不会触发错误。不要误写成`<=`。
</details>

**练习B：** 只把预算改为36元。地点和到达时间都不变，输出哪些数字变化？

<details><summary>参考推演</summary>

计算费用仍为37元，全组仍为111元。变化的是`budget_per_person`、`issues`和`valid`。预算不会反过来偷偷修改票价，也不会自动删站；修改方案属于规划者的职责。
</details>

**练习C：** 把人数从3改为5，是否应该更容易超出“每人37元”的预算？

<details><summary>参考推演</summary>

不应该。本项目按每人同价，没有团体折扣；每人仍为37元，全组变为185元。若将来支持团购，价格模型和测试都需要调整，不能只改显示文字。
</details>

**练习D：** 模型传给检查工具的预算为999元，但表单预算是30元，能直接接受工具的valid=True吗？

<details><summary>参考推演</summary>

不能。工具只检查它收到的参数，999可能是模型改写的。第7课的最终验证会用`TripRequest.check_arguments`重新带入表单的30元再算。这里先记住“谁提供约束”与“如何计算约束”必须分开。
</details>

## 8. 面试时怎样解释

对应题库[Q09–Q12](INTERVIEW_BANK.md#q09)。不要只说“加了规则校验”，要给出可以复算的例子：

> 我把HH:MM转换为从午夜开始的分钟数，按地点顺序累计访问时长、相邻交通时间和每人费用。比如公园11:30结束，去面馆15分钟，11:45到达是有效边界。检查函数返回所有冲突，规划层再据此修改方案。最终应用使用用户原始预算重算，防止模型在工具参数中放宽预算。

追问“为什么不用大模型算？”：金额、时间和边界可以由确定性函数准确复现，放在代码里方便测试；模型负责提出候选和调整选择。两者的责任不同。

追问“你处理了真实交通吗？”：没有，当前是教学网格估算；能讲清限制比说用了不存在的地图服务更可靠。
